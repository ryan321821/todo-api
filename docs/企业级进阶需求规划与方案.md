## 1. 现状盘点

当前项目已经具备：

| 层次 | 现状 | 可复用点 | 缺口 |
| :--- | :--- | :--- | :--- |
| `core/` | `config.py` 已集中配置；`security.py` 已内置 `bcrypt` 密码哈希与 `PyJWT` 令牌生成/解析 | JWT 工具可直接复用 | 缺少统一鉴权依赖、RBAC 模型 |
| `db/` | `engine` / `SessionLocal` / `get_db` 已封装，启动时 `create_all()` 自动建表 | 会话注入机制可复用 | 无迁移工具（Alembic），已有表结构变更困难 |
| `models/` | 已有 `Task` 与 `Category` 一对多 | 外键/`relationship` 写法可作为范式 | 无用户、角色、权限多对多模型 |
| `schemas/` | 已有 Task/Category 的 DTO/VO | `from_attributes` 配置可复用 | 无认证、用户、角色 Schema |
| `crud/` | 通用 `CRUDBase` + 单例对象 | 泛型基类可复用 | 无事务控制、多表联查、批量导入 |
| `api/` | 路由总线 + 版本前缀 | `include_router` 挂载范式可复用 | 无鉴权路由拦截、无文件上传下载 |

一句话结论：**骨架已经合格，缺的是"多租户身份、权限、缓存、复杂业务流"这四块企业级血肉。**

## 2. 企业级需求规划总览

围绕"进公司就能上手核心业务"这个目标，规划三大复杂度方向：

### 方向 A：复杂权限与安全控制（RBAC + JWT）

- 引入 `User` 表，账号唯一、密码 bcrypt 哈希、状态可禁用。
- 引入 `Role` 与 `Permission`，形成 `用户 <-> 角色 <-> 权限` 的多对多关系。
- 实现 JWT Token 登录鉴权、统一认证依赖注入、路由级权限拦截。
- 任务数据按 `owner_id` 归属用户，普通用户只能操作自己的任务，管理员可查看全部。

### 方向 B：性能与高并发优化（Redis 缓存层）

- 引入 Redis，对高频查询接口（如任务列表）做缓存。
- 采用 Cache-Aside（旁路缓存）策略，明确"命中缓存 / 回源 / 写后失效"流程。
- 设计数据一致性处理机制（先更新数据库、后删除缓存），并给出缓存故障降级策略。

### 方向 C：复杂业务与数据处理（Excel 导入导出 + 定时统计）

- 支持任务 Excel 批量导入（事务控制、行级校验、批量插入）与导出。
- 使用定时任务模拟 RPA 自动化场景，每日自动生成任务数据统计报表。

关系一句话总结：

- `users` 与 `roles`：**多对多**，通过 `user_roles` 关联表。
- `roles` 与 `permissions`：**多对多**，通过 `role_permissions` 关联表。
- `tasks` 与 `users`：**多对一**，`tasks.owner_id` 外键指向 `users.id`（任务归属）。
- `tasks` 与 `categories`：保持现有 **多对一** 关系不变。

### 4.2 已有表变更

`tasks` 表需要新增一列：

```text
ALTER TABLE tasks
  ADD COLUMN owner_id INT NULL,
  ADD INDEX ix_tasks_owner_id (owner_id),
  ADD CONSTRAINT fk_tasks_owner_id FOREIGN KEY (owner_id) REFERENCES users(id) ON DELETE SET NULL;
```

设计决策：

1. `owner_id` 设为 `NULL` 可空：让旧数据不需要强制迁移，历史任务可先保持 `NULL`，再由 DBA 统一回填给管理员。
2. `ON DELETE SET NULL`：删除用户时**不级联删除任务**，保留业务数据，只解除归属。
3. 迁移策略：新建表用 `Base.metadata.create_all()` 或 Alembic 自动生成；已有表用 `ALTER TABLE` / Alembic `op.add_column` 保留旧数据。

## 5. 权限矩阵设计

建议初始权限编码采用 `资源:动作` 格式：

| 权限编码 | 含义 | 初始 `user` 角色 | 初始 `admin` 角色 |
| :--- | :--- | :--- | :--- |
| `task:read` | 查看任务 | ✅ | ✅ |
| `task:write` | 创建/编辑任务 | ✅ | ✅ |
| `task:delete` | 删除任务 | ✅ | ✅ |
| `category:read` | 查看分类 | ✅ | ✅ |
| `category:write` | 创建/编辑分类 | ❌ | ✅ |
| `user:read` | 查看用户 | ❌ | ✅ |
| `user:write` | 管理用户 | ❌ | ✅ |
| `role:read` | 查看角色 | ❌ | ✅ |
| `role:write` | 管理角色 | ❌ | ✅ |

权限判断规则：

- `is_superuser=True` 的用户直接放行所有权限校验。
- 普通用户取其所有角色的权限编码并集，再判断是否包含所需权限。
- 资源归属（`owner_id`）与权限点分开判断：有 `task:read` 权限但任务不属于自己时，返回 403。

## 7. 缓存与数据一致性策略

### 7.1 缓存策略：Cache-Aside（旁路缓存）

```text
读请求：
  GET /tasks ──▶ Redis 有缓存？ ──是──▶ 直接返回
                    │否
                    ▼
               MySQL 查询 ──▶ 回写 Redis（带 TTL） ──▶ 返回

写请求：
  POST/PUT/DELETE /tasks ──▶ 先更新/删除 MySQL ──▶ 再失效任务列表缓存
```

### 7.2 关键决策

1. **缓存粒度**：缓存整个"列表响应"，而不是缓存单条任务。列表接口调用最频繁，收益最大。
2. **缓存键设计**：把用户、分页、筛选条件全部纳入 key，防止不同用户/参数串数据。
3. **写后失效顺序**：**先更新数据库，后删除缓存**。相比"先删缓存再更新库"，能避免"读旧库值写回缓存"造成的较长不一致窗口。
4. **缓存故障降级**：Redis 不可用时，读接口自动回源 MySQL、写接口忽略失效失败，保证主业务可用。
5. **TTL 兜底**：即使遗漏失效，缓存也会在 TTL 到期后自动淘汰，避免永久脏数据。

## 8. 环境与基础设施变更清单

### 8.1 新增中间件

在 `docker-compose.yml` 中新增 `redis` 服务：

```yaml
  redis:
    image: redis:7-alpine
    container_name: todo-redis
    ports:
      - "6379:6379"
    command: ["redis-server", "--appendonly", "yes"]
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 5
```

## 9. 开发顺序全流程

严格遵守"自底向上"的分层开发闭环：

```text
第 1 步：数据库设计 / 迁移
   └─▶ 设计新增表 + 已有表 ALTER，编写 SQL / Alembic 迁移
        │
第 2 步：ORM 模型（models/）
   └─▶ User / Role / Permission / 关联表，Task 增加 owner_id
        │
第 3 步：Pydantic 传输模型（schemas/）
   └─▶ auth / user / role / permission Schema，TaskResponse 增加 owner_id
        │
第 4 步：核心层（core/）
   └─▶ config 增加 Redis 配置，新增 seed 种子数据
        │
第 5 步：CRUD 持久层（crud/）
   └─▶ 事务控制、多表联查、selectinload 避免 N+1
        │
第 6 步：认证依赖注入（api/deps.py）
   └─▶ get_current_user / require_permissions / require_roles
        │
第 7 步：路由控制器（endpoints/）
   └─▶ auth / users / roles，改造 tasks 加鉴权与缓存
        │
第 8 步：路由总线与入口（api.py / main.py）
   └─▶ 注册路由、启动种子数据、Redis 缓存封装、定时任务
        │
第 9 步：验证与联调
   └─▶ 登录、鉴权、缓存命中、Excel 导入导出、定时统计
```

配套的**保姆级手写代码教程**见：`docs/RBAC权限与Redis缓存企业级实战保姆级教程.md`。
