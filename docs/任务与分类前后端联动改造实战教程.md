# 任务（Task）与分类（Category）前后端联动改造实战教程

> **核心提问**：将 `Task`（任务）和 `Category`（分类）在前端界面上关联起来，**后端需不需要改动？**  
> **答案**：**必须改动！**  
> 因为原有的 `Task` 是一张孤立的单表，数据库里没有记录任务属于哪个分类。要实现"创建任务选分类"、"任务列表展示分类标签（名称与颜色）"、"点击分类筛选任务"，后端必须从 **数据模型 -> 校验模型 -> 持久层 -> 路由控制器** 进行链路升级。

## 1. 📐 业务关联与架构设计原理

### 实体关系设计（一对多 / One-to-Many）

```text
┌─────────────────────────┐          ┌─────────────────────────┐
│     categories 表       │ 1      N │        tasks 表         │
├─────────────────────────┤          ├─────────────────────────┤
│ id (PK, INT)            │◀───┐     │ id (PK, INT)            │
│ name (VARCHAR, 唯一)    │    │     │ title (VARCHAR)         │
│ color (VARCHAR, 颜色)   │    └─────│ category_id (FK, INT)   │
│ description (TEXT)      │  外键关联│ priority (VARCHAR)      │
│ created_at / updated_at │          │ is_completed (BOOLEAN)  │
└─────────────────────────┘          └─────────────────────────┘
```

### 关键设计决策：
1. **为什么 `category_id` 设置为 `nullable=True`（可空）？**
   - 任务允许不归入任何分类（即"未分类任务"），降低用户操作负担。
2. **为什么外键级联设置为 `ondelete="SET NULL"`？**
   - 当用户删除某个分类时，属于该分类的任务**不应该被随之删除**，而是优雅地将 `category_id` 自动置为 `NULL`（变为未分类）。
3. **Pydantic 嵌套响应机制**：
   - 接口返回任务列表时，前端不仅需要 `category_id`，还需要分类的 `name` 和 `color` 来渲染彩色胶囊标签。
   - 通过在 `TaskResponse` 中嵌套 `category: Optional[CategoryResponse]`，FastAPI 会自动通过 SQLAlchemy 的 `relationship` 将关联的分类信息一并组装输出！前端不需要再发二次请求！

### 第一步：修改 ORM 模型（`app/models/task.py`）

**改动目的**：在 `tasks` 表中增加外键列 `category_id`，并建立与 `Category` 模型的 ORM 关联属性 `category`。

#### 修改后的完整代码：

```python
"""
ORM 模型层：Task（任务）数据表映射模型 (models/task.py)
"""

from sqlalchemy import Boolean, Column, DateTime, ForeignKey, Integer, String, Text
from sqlalchemy.orm import relationship
from sqlalchemy.sql import func

from app.db.base_class import Base


class Task(Base):
    """
    任务表 ORM 数据模型
    对应 MySQL 中的 `tasks` 表
    """

    __tablename__ = "tasks"

    id = Column(Integer, primary_key=True, index=True, autoincrement=True)
    title = Column(String(100), nullable=False, comment="任务标题")
    description = Column(Text, nullable=True, comment="任务描述")
    priority = Column(
        String(20),
        nullable=False,
        default="medium",
        comment="优先级: low/medium/high",
    )
    is_completed = Column(Boolean, default=False, comment="是否完成")

    # ==================== 【新增】所属分类外键关联 ====================
    # 外键：关联 categories 表的主键 id
    # ondelete="SET NULL": 分类被删除时，关联的任务不被删除，而是将分类ID置空 (NULL)
    category_id = Column(
        Integer,
        ForeignKey("categories.id", ondelete="SET NULL"),
        nullable=True,
        index=True,
        comment="所属分类ID",
    )

    # ORM 关系映射：允许在 Python 代码中直接通过 task.category 访问所属的 Category 对象
    category = relationship("Category", backref="tasks", lazy="joined")

    created_at = Column(
        DateTime(timezone=True),
        server_default=func.now(),
        comment="创建时间",
    )
    updated_at = Column(
        DateTime(timezone=True),
        server_default=func.now(),
        onupdate=func.now(),
        comment="更新时间",
    )

    def __repr__(self) -> str:
        return (
            f"<Task(id={self.id}, title='{self.title}', "
            f"priority='{self.priority}', category_id={self.category_id}, is_completed={self.is_completed})>"
        )
```

> 💡 **核心技术点解析**：
> - `lazy="joined"`：开启预加载（Eager Loading），SQLAlchemy 在查 `Task` 时会自动使用 `LEFT OUTER JOIN categories` 一并查出分类，避免后续出现 N+1 查询性能问题。

### 第二步：修改 Pydantic 数据传输模型（`app/schemas/task.py`）

**改动目的**：
1. 让 `TaskCreate` 和 `TaskUpdate` 支持接收客户端传入的 `category_id`；
2. 让 `TaskResponse` 响应体不仅包含 `category_id`，还包含完整的 `category: Optional[CategoryResponse]` 嵌套对象。

#### 修改后的完整代码：

```python
"""
数据传输层：Task 相关的 Pydantic 校验与响应模型 (schemas/task.py)
"""

from datetime import datetime
from typing import Optional
from pydantic import BaseModel, Field

# 导入分类的响应模型，用于嵌套在任务响应中
from app.schemas.category import CategoryResponse


# ==================== 客户端请求模型 (Request DTO) ====================


class TaskCreate(BaseModel):
    """创建任务时的请求体 (POST /tasks)"""

    title: str = Field(..., min_length=1, max_length=100, description="任务标题（必填）", examples=["完成项目文档"])
    description: Optional[str] = Field(None, max_length=500, description="任务详细描述（选填）")
    priority: str = Field(default="medium", pattern="^(low|medium|high)$", description="任务优先级: low/medium/high")
    
    # 【新增】可选的所属分类 ID
    category_id: Optional[int] = Field(None, description="所属分类ID（选填）", examples=[1])


class TaskUpdate(BaseModel):
    """更新任务时的请求体 (PUT /tasks/{id})"""

    title: Optional[str] = Field(None, min_length=1, max_length=100, description="任务标题")
    description: Optional[str] = Field(None, max_length=500, description="任务详细描述")
    priority: Optional[str] = Field(None, pattern="^(low|medium|high)$", description="任务优先级")
    is_completed: Optional[bool] = Field(None, description="是否已完成")
    
    # 【新增】支持更新所属分类 ID
    category_id: Optional[int] = Field(None, description="所属分类ID")


# ==================== 接口响应模型 (Response VO) ====================


class TaskResponse(BaseModel):
    """单个任务详情的返回数据模型"""

    id: int = Field(..., description="任务主键 ID")
    title: str = Field(..., description="任务标题")
    description: Optional[str] = Field(None, description="任务描述")
    priority: str = Field(..., description="任务优先级")
    is_completed: bool = Field(..., description="是否已完成")
    
    # 【新增】分类 ID 和嵌套的分类对象详情
    category_id: Optional[int] = Field(None, description="所属分类ID")
    category: Optional[CategoryResponse] = Field(None, description="所属分类对象信息")
    
    created_at: datetime = Field(..., description="创建时间")
    updated_at: datetime = Field(..., description="最后更新时间")

    model_config = {"from_attributes": True}


class TaskListResponse(BaseModel):
    """任务列表接口的返回数据模型 (GET /tasks)"""

    total: int = Field(..., description="符合条件的总任务数")
    tasks: list[TaskResponse] = Field(..., description="当前页的任务列表")
```

### 第三步：修改 CRUD 持久层（`app/crud/crud_task.py`）

**改动目的**：在 `get_multi_with_filter` 方法中支持 `category_id` 过滤条件，以便前端点击分类标签时，后端能准确筛选出该分类下的所有任务。

#### 修改后的完整代码：

```python
"""
数据持久层：Task 专属 CRUD 数据访问对象 (crud/crud_task.py)
"""

from typing import Optional
from sqlalchemy.orm import Session

from app.crud.base import CRUDBase
from app.models.task import Task
from app.schemas.task import TaskCreate, TaskUpdate


class CRUDTask(CRUDBase[Task, TaskCreate, TaskUpdate]):
    """
    Task 专属数据操作类
    """

    def get_multi_with_filter(
        self,
        db: Session,
        *,
        skip: int = 0,
        limit: int = 20,
        is_completed: Optional[bool] = None,
        priority: Optional[str] = None,
        category_id: Optional[int] = None,  # 【新增】分类ID筛选参数
    ) -> tuple[int, list[Task]]:
        """获取任务列表，支持状态、优先级、分类多条件筛选"""
        query = db.query(self.model)

        # 动态过滤：完成状态
        if is_completed is not None:
            query = query.filter(self.model.is_completed == is_completed)

        # 动态过滤：优先级
        if priority is not None:
            query = query.filter(self.model.priority == priority)

        # 【新增】动态过滤：所属分类
        if category_id is not None:
            query = query.filter(self.model.category_id == category_id)

        # 排序与分页
        query = query.order_by(self.model.created_at.desc())
        total = query.count()
        tasks = query.offset(skip).limit(limit).all()

        return total, tasks


task = CRUDTask(Task)
```

### 第四步：修改路由控制器（`app/api/v1/endpoints/tasks.py`）

**改动目的**：
1. 在 `GET /tasks` 接口中接收 `category_id` 查询参数并传给 CRUD；
2. 在创建和更新任务时，如果用户传了 `category_id`，先校验该分类在数据库中是否存在（不存在则返回友好的 `400 Bad Request`）。

#### 修改后的完整代码：

```python
"""
路由控制器层：Task 任务业务端点 (api/v1/endpoints/tasks.py)
"""

from typing import Optional
from fastapi import APIRouter, Depends, HTTPException, Query, status
from sqlalchemy.orm import Session

from app import crud
from app.db.session import get_db
from app.schemas.msg import MessageResponse
from app.schemas.task import TaskCreate, TaskListResponse, TaskResponse, TaskUpdate

router = APIRouter()


@router.post("", response_model=TaskResponse, status_code=status.HTTP_201_CREATED, summary="创建新任务")
def create_task(task_in: TaskCreate, db: Session = Depends(get_db)):
    """创建新任务（包含可选分类）"""
    # 【新增业务校验】：若指定了分类ID，检查该分类是否存在
    if task_in.category_id is not None:
        db_category = crud.category.get(db=db, id=task_in.category_id)
        if not db_category:
            raise HTTPException(
                status_code=status.HTTP_400_BAD_REQUEST,
                detail=f"指定的分类 ID {task_in.category_id} 不存在",
            )
    return crud.task.create(db=db, obj_in=task_in)


@router.get("", response_model=TaskListResponse, summary="获取任务列表")
def read_tasks(
    skip: int = Query(0, ge=0, description="分页跳过条数"),
    limit: int = Query(20, ge=1, le=100, description="每页返回条数"),
    is_completed: Optional[bool] = Query(None, description="按完成状态筛选"),
    priority: Optional[str] = Query(None, description="按优先级筛选"),
    category_id: Optional[int] = Query(None, description="按分类ID筛选"),  # 【新增】分类查询参数
    db: Session = Depends(get_db),
):
    """获取任务列表，支持多维组合筛选"""
    total, tasks = crud.task.get_multi_with_filter(
        db=db,
        skip=skip,
        limit=limit,
        is_completed=is_completed,
        priority=priority,
        category_id=category_id,
    )
    return TaskListResponse(total=total, tasks=tasks)


@router.get("/{task_id}", response_model=TaskResponse, summary="获取单个任务详情")
def read_task(task_id: int, db: Session = Depends(get_db)):
    """获取单个任务详情"""
    db_task = crud.task.get(db=db, id=task_id)
    if db_task is None:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail=f"任务 ID {task_id} 不存在")
    return db_task


@router.put("/{task_id}", response_model=TaskResponse, summary="更新任务信息")
def update_task(task_id: int, task_update: TaskUpdate, db: Session = Depends(get_db)):
    """更新任务（支持局部修改分类ID）"""
    db_task = crud.task.get(db=db, id=task_id)
    if db_task is None:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail=f"任务 ID {task_id} 不存在")

    # 【新增业务校验】：若修改了分类，检查新分类是否存在
    if task_update.category_id is not None:
        db_category = crud.category.get(db=db, id=task_update.category_id)
        if not db_category:
            raise HTTPException(
                status_code=status.HTTP_400_BAD_REQUEST,
                detail=f"指定的分类 ID {task_update.category_id} 不存在",
            )
    return crud.task.update(db=db, db_obj=db_task, obj_in=task_update)


@router.delete("/{task_id}", response_model=MessageResponse, summary="删除任务")
def delete_task(task_id: int, db: Session = Depends(get_db)):
    """删除指定任务"""
    db_task = crud.task.get(db=db, id=task_id)
    if db_task is None:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail=f"任务 ID {task_id} 不存在")
    crud.task.remove(db=db, id=task_id)
    return MessageResponse(message=f"任务 ID {task_id} 已删除", id=task_id)
```

## 4. 🐳 Docker 环境生效与 MySQL 表结构同步（重要避坑）

> ⚠️ **关键注意点**：  
> 因为你的 `tasks` 表在之前已经由 MySQL 创建好了，`Base.metadata.create_all()` **不会自动对已经存在的表去执行 ALTER TABLE** 添加 `category_id` 列。

### 怎么让 MySQL 表结构拥有 `category_id` 列？（两种方法任选其一）

#### 方法 A（最简单推荐：一键清空旧卷重建）
在项目根目录打开终端执行：
```bash
# 停止容器并删除旧的数据库数据卷
docker compose down -v

# 重新构建启动，lifespan 会自动按照最新的模型创建包含外键的 tasks 表
docker compose up --build
```

#### 方法 B（保留原有数据：进入 MySQL 执行 ALTER TABLE）
在终端中执行：
```bash
docker compose exec db mysql -u todo -ptodo -e "USE todo; ALTER TABLE tasks ADD COLUMN category_id INT NULL, ADD CONSTRAINT fk_tasks_category FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE SET NULL;"
```
